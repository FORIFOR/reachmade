# Reachmade Product Film System — 2026-09-25

## 目的

6製品の動画を「既存録画の短縮版」から、**実製品の象徴的な1シーンを中心にしたブランドフィルム**へ更新する。

映像の目的は機能を列挙することではなく、最初の10秒で「この製品は何を変えるのか」を理解できること。製品UIそのものは生成AIで描き直さず、実録画だけを使う。

正本は `src/film-briefs.mjs`。この文書は制作手順と公開ゲートを説明する。

## 4フォーマット

| 形式 | 目安 | 役割 |
|---|---:|---|
| Hero Loop | 10秒 | LP最上部。muted / loop / playsinline |
| Product Film | 55秒 | LP・YouTube・GitHubの主映像 |
| Vertical Cut | 20秒 | X / Shorts / TikTok |
| Full Demo | 120秒 | 実装評価・導入検討用 |

1回のMaster Captureから4形式を作る。9:16は16:9の単純クロップではなく、UIの見せたい領域を縦画面向けに再構成する。

## 絶対ルール

1. 製品UIのピクセルは実録画のみ。
2. 再生速度は原則1.0倍。待ち時間を省く場合はカットで処理し、速度を上げない。
3. 生成AIは背景B-rollや非製品部分には使用できるが、製品画面を生成・補完・文字改変しない。
4. 1フレーム1メッセージ。説明字幕を画面いっぱいに置かない。
5. 「Experience → Value → Proof → Limits」の順で見せる。
6. 音は音楽よりUIの意味を優先する。製品ごとに2〜4種類の固有SFXまで。
7. 自動再生はHero Loopだけ。reduced-motion / saveDataでは静止画へ落とす。
8. 縦動画でも機能を減らさず、カメラ位置とレイアウトを変える。

## 6製品の象徴シーン

### Genie

**作業を止めずに、考えを前へ。**

通常のMac作業 → TaskDock → その画面について質問 → 回答 → 必要部分をコピー → 元の作業が前面のまま。

製品の価値は「別のAI画面を開くこと」ではなく、今の仕事にAIを重ねること。

### AI Meeting

**話したことが、次の行動になる。**

AIとの会話 → ユーザーが割り込み → 予定変更 → Pending → 確認 → タスクへ反映。

一番見せたいのはアバターではなく「会話が確定済みの次の行動として残る瞬間」。

### Oathra

**AIの「できた」ではなく、相手の言葉で確かめる。**

AI側が成功を宣言 → 判定はまだPending → 相手側発話から日時・人数・確定を取得 → VERIFIED。

Oathraの差別化は自然な電話音声だけではなく、完了判定をAIの自己申告から切り離していること。

### AI Secure

**送る前に、ローカルで確かめる。**

文書 → 「送信せずに検査」 → review/保留 → 理由とcoverage → JSONレポート。

「検出なし＝安全」を演出しない。現在見逃すカテゴリがあることも、証拠として見せる。

### Agent Team

**ひとつ頼む。チームが作り、確かめ、直す。**

依頼 → Master → Researcher / Builder → Reviewer → 指摘クリック → 成果物の該当箇所 → 修正版 → re-verification。

完成した答えより「誰が何を確かめ、どこが変わったか」が主役。

### Launchloom

**作ったものを、公開できる素材へ。**

実録画 → Storyboard → 16:9 → 9:16 → LP → 投稿案 → review-ready launch kit。

SNS自動投稿の成功を見せるのではなく、公開前に確認できる素材一式までを見せる。

## LPの新しい順序

1. Hero — 一言の価値 + Hero Loop
2. THE MOMENT — その製品が一番伝わる象徴シーン
3. WATCH IT HAPPEN — 実録画
4. FLOW — 3〜4段階の体験
5. PROOF — 保存成果物・検証記録・GitHub
6. CURRENT BOUNDARIES — 未検証・条件
7. CTA — Try / GitHub / Reachmadeへ相談

今回のブランチではTHE MOMENTを先に実装し、動画差し替え前でも物語の順序を固定する。

## 撮影

- Retina / 4K相当の解像度。
- 通知、個人情報、無関係なメニューバー項目を消す。
- デモデータは固定して、同じ操作を何度でも再現できるようにする。
- カーソル移動を演出しすぎない。結果変化を主役にする。
- 収録時にUIを拡大せず、編集側でcrop/panして視線を誘導する。
- 重要操作の前後に0.5〜1.0秒の余白を残す。

## 編集

- hard cutを基本にする。
- UIの位置関係を保てる箇所だけmatch cut / morph。
- ズームは1.05〜1.15程度。過剰な疑似カメラワークをしない。
- 字幕は一度に1〜2行。
- エンドカードは全製品共通で2〜4秒。
- Reachmadeのsonic markは全製品共通、製品SFXは別。
