# シグネチャーシーン（2026-09-19）

VoiceOSのトップページを分解した所見（Heroが1本の動画ではなく、背景画像・光沢・アプリUI・テキストを別レイヤーに分けてDOMで組み立てていること、アプリ一覧が同じDOMを2セット持つ無限マーキーであること）を、Reachmadeの構成に翻訳した変更です。

リリース識別子：`data-signature-scene-version="20260919-signature-1"`

## 技術選定について（先に相違点を書きます）

参考資料はNext.js / React / Motion構成を前提にしていますが、このサイトは**npm依存ゼロの静的サイト**です（`package.json`に依存パッケージなし、CSPは`script-src 'self'`、テストが外部依存の混入を禁止）。フレームワークを入れることはサイト全体の作り直しになるため、**同じ技法をバニラJS + CSSで実装**しました。得られる結果は同じで、ビルド段数とバイト数は増えません。

| 参考資料 | 本実装 |
|---|---|
| React state + Motion | `data-state` / `data-step-state`属性をJSが切り替え、遷移はCSSが担当 |
| `useScroll` + `useTransform` | `scrollProgress()`（要素の矩形と視野高から0→1を算出） |
| marqueeのDOM二重化 | 同一の`<ul>`を2つ、2つ目は`aria-hidden="true"` |
| Next Image最適化 | 画像を使わない。背景・光・グリッドはすべてCSS |

## 入れたもの

### 1. シーンエンジン `public/assets/signature-scene.mjs`

`[data-signature-scene]`を見つけて、`data-state`と各ステップの`data-step-state`（`waiting` / `current` / `done`）を進めるだけの小さなエンジンです。見た目の変化はすべてCSS側にあります。

- **全ステップがHTMLに存在します。** JavaScriptが動かなくても物語は最後まで読めます。
- 画面内に入ったときだけ再生。`prefers-reduced-motion`と通信量節約設定では**最終状態を静止表示**します。
- 再生／停止とステップ選択の実ボタンを持ちます（`hidden`をJSが外すため、非対応環境に死んだUIを出しません）。
- `data-scene-scroll`を付けると自走せず、**読み手のスクロールが再生ヘッド**になります。スクロールの乗っ取り（pin）はしません。
- ネットワーク・保存・マイクを使いません。既存の`animated-demos.mjs`（製品内の18秒UIストーリー）は置き換えず、そのままです。

### 2. トップ：一つの仕事が、道具を渡り歩く

ファーストビュー右側が、録画のポスターから**6状態のシーン**になりました。00 待機 → 01 依頼 → 02 AI Meeting → 03 Agent Team → 04 Launchloom → 05 手元に残るもの。製品名から各製品ページへ移動できます。

**正直さの制約**：6製品は独立した別プロダクトです。自動連携する単一パイプラインではありません。シーンの注記にそのまま書いています（「6つは独立した製品で、自動で連携する単一のパイプラインではありません。ここで実行・保存・投稿は行いません。」）。

その直下に「REAL RECORDING / GENIE — 上の場面は説明のための再現UIです。こちらは実アプリの録画と、そこで保存された成果物。」を置き、**主張 → 証拠**の順に読めるようにしました。VoiceOSのトップには対応する証拠面がありません。

### 3. トップ：入力と、残るもの（マーキー）

6製品の「入力 → 成果物」を台帳から取り出し、同じ`<ul>`を2つ並べて`translateX(-50%)`で流します。2つ目は`aria-hidden="true"`。`prefers-reduced-motion`では流れを止め、折り返しの一覧として表示します。

### 4. 全12製品ページ：この製品の流れ

各製品ページのファーストビュー末尾に、その製品の`outcome`（例：`通話 → 発言の根拠 → 結果`）から生成した進行レールを追加しました。**スクロール連動**で、読み進めると段が進みます。文言は台帳が唯一の出典で、ここで新しい主張を作っていません。

## 検証したこと

- `npm run check`：ビルドと**351件**のNodeテストが通過（今回の新規19件を含む）。
- エンジンは偽DOMで実フレームを流して検証：初期状態、進行、ステップ選択での一時停止、`prefers-reduced-motion`での最終状態固定、スクロール連動の0↔完了、二重マウント拒否、破棄後の後片付け。
- 実ビルドをローカルHTTPで配信し、Chromiumで確認：シーンの各状態（01/03/05）の表示、マーキー、12製品ページすべてにレールが1つずつ入っていること、HTMLのscript/stylesheetが各1本のままであること、390px/1440pxでの横溢れなし。
- **`--force-prefers-reduced-motion`で実ページを表示し、シーンが最終状態で静止することを確認**しました（エンジンがブラウザで実際に動作していることの確認でもあります）。

## 検証していないこと

- **自走再生の実機確認**。手元のheadless Chromiumは`requestAnimationFrame`のフレームを生成しないため、時間経過による状態遷移をこの環境では観測できませんでした。タイムラインの計算とフレーム加算はNodeのテストで検証しています。実ブラウザでの見え方は、CIのPlaywright（Chromium / WebKit）結果を確認してください。
- Safari・iPhone実機、VoiceOver、低電力モード。
- 本番配信。このコミットはデプロイしません。
- VoiceOSとの優劣は測定していません。構造上の差分を埋めた、という記述に留めます。
