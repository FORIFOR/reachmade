# 日英LP：相談と製品評価への入口を整理

## 変更の目的

初訪問者が何を開発するラボかを理解し、企業相談か製品評価へ進めるようにする。
日本語・英語とも同じ情報順と操作を使い、言語を切り替えても目的が変わらないようにする。
企業の開発相談を主操作に置くのは実装上の判断であり、コンバージョン改善の実測ではない。
生成り・墨色・朱色の句点、外部フォントなし、npm依存なしを維持する。

## 最終構成

1. 開発支援の説明、相談CTA、手動で選ぶ製品映像を同じ入口に配置。
2. 企業向け開発支援。
3. 夜澄ノアを含む7製品の用途・成果・具体的な利用入口。映像と詳細条件はnative detailsに保持。
4. 開いて比較できる利用条件・ライセンス表。
5. 設計方針と開発者・検証記録へのリンク、FAQ、相談CTA。

共有プレイヤーの説明は選択中の映像に追随する。Oathraはイメージ映像、Agent Teamは設計動画、
夜澄ノアは画面を再現した紹介映像と表示し、実録画と混同しない。
Oathra／Agent Teamの映像の説明と、台帳上の実行記録の説明は分けて保持する。
TaskDockの未リリース設計は製品ページへ誘導する。
静止画の自動切替・ズーム・入場待ち時間はなく、動画は選択だけでは再生しない。
ネイティブの再生・一時停止・シーク・全画面操作を維持。製品詳細を閉じると、その動画を止める。
映像タブからTabキーで再生ボタンへ進め、枠内に白と緑のフォーカスを表示する。
画像の種類（実画面・レポート・再現映像）をカードにも表示。作品名だけでなく短い用途を映像選択欄に添える。
旧ホーム専用の4モジュールは、現行ホームでは読み込まない。製品ページでの利用は保持する。
生成処理は自身のCSS/JS層だけを更新し、後段の製品ページ層を保持する。

## 検証と証拠

観察可能な条件は `docs/design/lp-quality-acceptance-2026-09-30.md` のL1〜L14に記録する。
ビルドと全Nodeテストは `npm run check`、Chromium/WebKitの操作・媒体検証はPRの各CIで実行する。
旧ホームの `.studio-player` / `.lab-signature` を前提とした検証は、現行の手動選択式ホームに更新。
製品ページの既存機能、媒体hash・codec・配信経路、ネイティブ再生は引き続き確認する。
JS無効・reduced-motion・ネットワーク中断からの再試行も、実際のページ・媒体を使う。
架空の成功応答や新しいモック・ダミーデータは追加していない。

Codex In-app Browserで現在の実ビルドを確認した結果:

- 日英とも320 / 390 / 768 / 960 / 1024 / 1440 / 1920 CSS pxで横overflowなし、7製品を表示。
- 1280×720で日英の主CTAは画面内。390×844でも相談と製品評価の両入口が画面内。
- 映像タブのEndキーでNoaを選択し、Tabで再生ボタンへ移動。フォーカス枠を実画面で確認。
- 選択のみではsrc未設定。明示的なEnterで実媒体を再生し、ネイティブcontrolsと時刻進行を確認。
- 本文・補足・選択欄・ボタン・朱色ラベルの計算済み文字色/背景色10組は4.80〜15.89:1。
  画像内の文字や全サイトのWCAG適合を示す検査ではない。

実画面JPEGと実測JSONは `artifacts/ui/lp-clarity/` に保存（Git管理外）。
`.claude/skills/ui-craft/SKILL.md` と設計資料を使用。
参照されるfrontend-designは未導入だったため、使ったとは記載しない。
